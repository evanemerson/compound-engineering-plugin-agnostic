# Review Findings — 2026-07-31 15:25 (PR #29)

**Subject:** branch `chore/model-pin-control-harness`, commit `d9c050e` — the
control suite for `scripts/check-model-pins.sh`.

**Through-line:** the PR shipped a control suite whose purpose is to prevent
"a suite that only exercises the branch it happens to reach," and the suite
reproduced that defect one grain coarser: **22 of its 26 cases targeted leg 4**
— the region the recorded case list was transcribed from — and **12 material
single-line mutants of the checker survived it at 26/26**. Independently, it
**dropped three recorded cases (21-23)** while four artifacts claimed all 24
had landed, with arithmetic that does not close (24+1+4=29, not 26). Three
agents caught the drop independently.

Both are the same failure as the incident the PR exists to close. That is the
finding worth keeping: building the harness the solution doc asked for
produced a fresh instance of the defect the solution doc is about, which is
strong evidence the **case-list framing**, not the execution method, was the
load-bearing mistake. The fix generalizes it — `cepa:autonomy` §9f now
requires every control to name the mutant it kills, so "which branches have a
control" has a mechanical answer.

**Verification after fixes:** 47 controls, all passing; **20 single-line
mutants built with build-time assertions, all 20 now caught**; checker 0 MISS
/ 0 WARN; tree clean; no fixture leaks.

- title: The fixture builder silently dropped files and the baseline gate accepted the truncated tree
- applied_in: "this branch — set -o pipefail, a tracked-but-unreadable FATAL, and a post-extract file-count assertion"

**Problem:** two holes composed. The fixture is materialized by a pipeline
and `pipefail` was not set, so the `|| FATAL` guard saw only the *extract*
stage; GNU tar skips an unreadable member, writes a valid archive and exits
2, and the reader exits 0. The `[ -e "$p" ]` pre-filter tests existence, not
readability. Then the baseline gate asserts only `0 MISS / 0 WARN`, and a
tree missing files is *cleaner*, not dirtier. Reproduced: with one tracked
file unreadable (`chmod 000` on `plugins/cepa/commands/review.md`, the file
CLAUDE.md records as having carried four live unpinned dispatch sites), the
real checker reports 3 MISS while the suite reported `baseline: 0 MISS` and
`26/26 controls passed`. Every claim the suite makes is a claim about a tree
it did not finish building.

**Fix:** `set -o pipefail`; a tracked-but-unreadable path is now FATAL rather
than skipped; and after extraction the file count is compared against the
filtered list, which also closes the TOCTOU window `pipefail` alone leaves
open.

### 7
- status: applied
- severity: P2
- agent: security-sentinel
- category: security
- confidence: 100
- action_class: mechanical
- file: scripts/check-model-pins-controls.sh
- lines: 325-332, 245, 275 (pre-fix)
- title: A tracked symlink survives fixture materialization, and planting writes follow it outside the fixture
- applied_in: "this branch — refuse-and-abort guard on the pristine fixture, before any case runs"

**Problem:** `git ls-files | tar` preserves symlinks as symlinks, and `cp -a`
preserves them per case. `say()`'s `>>` append and the `cat >` plants use
shell redirection, which **follows** symlinks. A branch that replaces the
tracked `README.md` or `CLAUDE.md` with a symlink to any path the invoking
user can write turns a run of this suite into an arbitrary-file append or
truncate outside the repo — and CLAUDE.md now instructs maintainers to run it
whenever they touch the checker. Reproduced independently by two parties: the
append landed in a file outside the fixture. Content is fixed by the script,
so this is not general RCE; the realistic risk is a developer running the
audit tool on a colleague's or contributor's branch on their own workstation.
CI blast radius is low (ephemeral, `contents: read`, no secrets).

**Fix:** refuse to run when the pristine fixture contains any symlink, naming
the paths. `tar --dereference` was rejected as the alternative — it would
trade this for pulling the linked file's *content* into the fixture. Case
L1d plants its own symlink after the copy, which the guard correctly does not
constrain.
