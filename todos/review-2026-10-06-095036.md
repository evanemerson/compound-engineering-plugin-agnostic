# Review — PR #87, worktree-coordinator write guard

Five agents. No P1. Three agents independently found that the first cut's
"PARKED → proceed as written" did not survive contact with the commands: a
PARKED coordinator's own `/cepa:task` created its branch and then its
`/cepa:plan-review` and `/cepa:review` sub-steps re-measured, read NOT-PARKED,
and dropped their findings outside `todos/`. The fix is a redesign of §10f,
applied on this branch: only task and lfg run the probe; a PARKED run is a
worker run whose steps take its verdict; sweep, resolve-pr and weekly review
stop; the other commands run report-only in every state when a coordinator
invokes them directly. Judgment-class items applied here are the worker's own
branch decisions, listed in the Handoff block.

title: Sub-commands re-measure and drop a PARKED run's findings

**Problem:** task → plan-review → review each re-ran the probe on the run's
own new branch, went report-only, and wrote findings to the git-dir; lfg
then parsed `todos/` and saw none. §10f also promised "a committing run
branches first", a step no committing command had.

**Fix:** only task and lfg run the probe. A PARKED run is a worker run for its
whole length; every command it invokes as a step takes its verdict and never
re-measures. Direct invocations of the other commands are report-only in
every state, so no "branch first" promise is needed outside task and lfg,
which already branch. The unused allowed-tools grants are reverted.
