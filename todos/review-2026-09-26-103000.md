### 1

- status: applied
- severity: P1
- agent: adversarial-reviewer, silent-failure-hunter, previous-comments-reviewer
- category: correctness
- confidence: 98
- action_class: corroborated
- file: plugins/cepa/commands/compound.md
- lines: 271
- title: `P="$P.scrubbed"` did not survive to the writeback block

**Problem:** The reassignment ran in the fenced block ending at line 279;
`writeback "$P"` runs in a separate block starting at 306. Each fenced block
is its own shell — a rule this repo already documents one file over — so `$P`
was unset at the POST and fell back to the unscrubbed original. Measured: no
variable (`$P`, `$CLIENT`, `$REPO`) survives a block boundary.

This was the same leak the PR existed to close, moved one block later, and
strictly weaker than the `mv` it replaced: a failed `mv` at least errored
sometimes.

**Fix:** Applied in `b51ab8e`, then corrected in `4e2fcf9`. The same-path
install is right, but `cat > "$P"` truncates before reading and silently
destroyed the payload on an empty sidecar (finding 10). It is now
`[ -s ]` + `mv -f`, which is atomic and cannot leave a truncated target.

### 9

- status: applied
- severity: P1
- agent: adversarial-reviewer
- category: correctness
- confidence: 95
- action_class: judgment
- file: plugins/cepa/scripts/brain-client.sh
- lines: 175-188
- title: The same-path guard compared spellings, so symlinks and hardlinks destroyed the payload at exit 0

**Problem:** The guard built `dirname`+`basename` strings and compared those.
A symlinked infile or a hardlinked outfile resolves to a different *path*
while being the same *file*, so the guard passed, the redirect truncated the
target, `sed` read the now-empty file through the link, and **scrub exited 0
with the payload destroyed**.

That is verbatim the `scrub f f` failure the guard's own comment claims it
killed "for every caller". It killed one spelling. Measured both forms: rc=0,
victim 0 bytes.

Downstream it was luck, not design, that nothing egressed: the next line's
`chmod` failed on a missing file and `set -e` aborted — with a message about
permissions, no suppression record, and an emptied `$P` on disk.

**Fix:** Applied in `4e2fcf9`. Resolve with `readlink -f` and compare inodes
so hardlinks are caught. Verified both refused rc=2 with the victim intact,
and normal / same-path / outfile-symlink / new-file / missing-dir all
unregressed.

### 10

- status: applied
- severity: P1
- agent: adversarial-reviewer
- category: correctness
- confidence: 95
- action_class: judgment
- file: plugins/cepa/commands/compound.md
- lines: 297-301
- title: An empty sidecar silently destroyed the payload

**Problem:** `cat "$P.scrubbed" > "$P"` truncates `$P` before reading. If the
sidecar was empty — reachable via finding 9, or a full disk — `cat` succeeded,
so the `||` gate could not see it. The payload was emptied, the sidecar
deleted, and the block exited 0. `_assert_envelope` then rejected the empty
payload one verb later as a confusing error, with the evidence already gone,
and the non-zero exit disabled the brain for the rest of the run.

A genuinely partial write is handled — `cat` exits non-zero and the gate
fires. Only the empty case slipped through.

**Fix:** Applied in `4e2fcf9`. `[ -s "$P.scrubbed" ]` before installing, and
`mv -f` instead of `cat >` — atomic within a directory, so it cannot leave a
truncated target. Verified: empty sidecar suppresses rc=1; good sidecar
installs at mode 600 with the sidecar removed.

`--git-common-dir` → present.

That was wrong, and this is why the claim was re-derived rather than accepted.

**Fix:** Applied in `4e2fcf9`. Use
`--path-format=absolute --git-common-dir`, mirroring the `.env.local`
resolution. Verified end to end in a throwaway worktree, since removed.
