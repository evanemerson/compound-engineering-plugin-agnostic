# Review — PR #72 (compound.md executable PHI-scrub gate)

Five agents. **The gate shipped in `86db93c` did not protect the writeback** —
three agents found that independently, and the orchestrator's own trace found
it before the first agent returned. All P1s fixed in `b51ab8e` (v1.26.9).

Two agents also correctly noted the fix was sitting uncommitted at the time
they read the tree. It is committed now.

### 1

- status: applied
- severity: P1
- agent: adversarial-reviewer, silent-failure-hunter, previous-comments-reviewer
- category: correctness
- confidence: 98
- action_class: corroborated
- file: plugins/cepa/commands/compound.md
- lines: 271
- title: `P="$P.scrubbed"` did not survive to the writeback block

**Problem:** The reassignment ran in the fenced block ending at line 279;
`writeback "$P"` runs in a separate block starting at 306. Each fenced block
is its own shell — a rule this repo already documents one file over — so `$P`
was unset at the POST and fell back to the unscrubbed original. Measured: no
variable (`$P`, `$CLIENT`, `$REPO`) survives a block boundary.

This was the same leak the PR existed to close, moved one block later, and
strictly weaker than the `mv` it replaced: a failed `mv` at least errored
sometimes.

**Fix:** Applied in `b51ab8e`. Install the scrubbed bytes at the SAME path
(`cat "$P.scrubbed" > "$P"`), so nothing has to cross a shell boundary.

**Problem:** `scrub`'s `>` redirect created the outfile at the process umask —
measured 644 — and wrote scrubbed doc content into it before any caller's

the outfile 600 before any content lands, and refuse to write through a
symlink. Verified the victim file was untouched and the same-path,
missing-dir, and overwrite cases did not regress.

**Problem:** `compound-refresh.md` scrubs unconditionally on every writeback;

ambiguous — an operator decision, not a drive-by fix.

re-derives the rule rather than instantiating it. That objection is fair and
points at the same fix.

**Fix:** Deferred — residual 2h. Resolve the policy in SKILL.md first, then
make both commands match, ideally by moving detection into `brain-client.sh`
(a `scrub-required` verb) so the rule lives in one executable place.
