- title: The PR's own flagship correction destroyed valid data and called it unrecoverable

**Problem:** That file has a `### 21-25` heading — a batch block covering five
enumerated findings under one `severity:`/`status:` pair. A per-line tally reads
26 findings against `total: 30` and looks like drift. Expanded it is
**1 P1 + 15 P2 + 14 P3 = 30**, exactly the declared total — corroborated by the

edit. The PR shrank `total` to 26 and asserted four findings were "not
recoverable". They were never lost.

**Fix:** Reverted. `total: 30` restored, `p2`/`p3` un-transposed (the file's real
pre-existing defect), false note replaced with one explaining the blind spot.
**Applied.**

### 2
- status: applied
- severity: P1
- agent: silent-failure-hunter, security-sentinel
- category: silent-pass
- confidence: 100
- action_class: corroborated
- file: plugins/cepa/skills/file-todos/SKILL.md
- lines: 203
- title: The prescribed verification returned zero rows, silently, on most of the corpus

**Problem:** Both commands were anchored to `^- severity:`. Two field formats are
live; on the bare `severity:` form they return **0 rows for every value**, not an
error. That is 4 of the 6 files this PR corrected and claims to have verified
with them, plus 7 files corpus-wide. A check that does not fire, shipped as the
fix for checks that assert the wrong thing.

**Fix:** `grep -oE '^-?[[:space:]]*severity: P[123]'`, plus the rule that a zero
count means the pattern missed, not that the file is clean. **Applied.**

### 4

- title: The invariant was stated as equality but written as an inequality

**Problem:** `gap ≤ skipped` is satisfied by `gap 0 / skipped 0` — precisely the
shrink-`total` encoding being rejected. A file could absorb any number of

**Fix:** Equality, with one mandated encoding (`total` never shrinks; removals

`p1`/`p2`/`p3` cannot be re-derived once a removal has happened. **Applied.**
