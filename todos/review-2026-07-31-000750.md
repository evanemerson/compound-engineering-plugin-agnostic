- title: A tab delimiter collapsed the leading empty field, silently dropping every unqualified citation — including CLAUDE.md's own §9a-§9f block
- applied_in: "this branch — `|` delimiter, which the qualifier charset cannot contain"

**Problem:** Rows were emitted as `${qual}\t${anchor}` and read back with
`IFS=$'\t' read -r q a`. Tab is IFS **whitespace**, so `read` collapses a
leading empty field. A citation with no word token before the `§` —
line-initial `§9c`, `(§2b`, `"§9c"`, `— §9c`, or a token the leading-dash
sanitizer blanked — produced `q=<anchor>`, `a=""`, and the loop's
`[ -n "${a:-}" ] || continue` dropped it before any check.

Verified directly:

```
$ printf '\t9q\nautonomy\t9c\n' | while IFS=$'\t' read -r q a; do printf 'q=[%s] a=[%s]\n' "$q" "$a"; done
q=[9q] a=[]          <-- anchor landed in q; a empty; row dropped
q=[autonomy] a=[9c]
```

Instrumenting the real script showed which anchors died: `2b, 9a, 9b, 9c, 9d,
9e, 9f` — **every anchor this repo defines**. 26 live occurrences across 12
files landed in the dropped branch, including `CLAUDE.md:67-70`, the exact
block citing §9a-§9f that leg 4 exists to protect.

**Why the negative controls missed it — the finding inside the finding.** All
four round-1 controls were written with a word before the `§` (`# temp §9z`,
`§9c-9z` after "autonomy", `` `grounding` §9c ``, `# temp §9y`), so all four
took the surviving path. The unqualified path was validated zero times. A
detection change and the thing it detects, landing together, hid each other —
§9f's own rule, occurring inside the gate it governs.

**Fix:** Use `|`, which the qualifier charset `[A-Za-z0-9_.:-]` cannot
contain. Then re-run the controls **in unqualified shape** and keep one of
each shape on record so the next widening cannot re-validate only the
reachable branch.
