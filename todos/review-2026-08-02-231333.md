title: Reused fixed transcript path can serve mutant N-1's transcript as mutant N's result

**Problem:** `> "$WORK/controls.out"` reuses one path for every mutant with no
pre-clear, and both the subshell/redirect status and `cat`'s status are
discarded. If the open-for-truncate fails (EACCES/EROFS/quota — reproduced
with chmod 444) or the fork fails, the PREVIOUS mutant's complete transcript
survives and classifies this mutant — dominant wrong token is a false CAUGHT,
the repo's documented dominant defect class. The old `$( )` pipe structurally
could not deliver another run's output: this is a regression introduced by the
1.18.2 hardening. Security-sentinel independently flagged the same reused path
as symlink-followable by a mutated checker (conf 35, capped: the threat model
already grants the mutant arbitrary execution as the same user). Reliability's
fd trace confirms orphans cannot write the file — the trigger is open failure,
not interference.

**Fix:** `rm -f "$WORK/controls.out" || FATAL exit 2` immediately before the
redirect — a failed redirect then yields a MISSING file → `out=''` → no
trailer → HARNESS-ERROR → exit 2, the already-correct path. Also unlinks any
planted symlink instead of following it.
