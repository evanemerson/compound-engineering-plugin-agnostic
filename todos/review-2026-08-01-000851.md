- lines: 60-72
- title: Baseline gate aborts before any control runs

**Problem:**
Raised independently by adversarial, coherence and feasibility, each reproducing
it. The controls harness runs a baseline gate BEFORE its runner loop
(`scripts/check-model-pins-controls.sh:711-718`) and FATALs with `exit 1` if the
mutated checker's verdict on the clean tree is not 0 MISS / 0 WARN. For every
mutant that tightens or loosens the checker's verdict on the repo's own content,
zero controls execute. A driver classifying on exit status scores that CAUGHT and
reports green having proven nothing; a driver parsing FAIL lines sees no failed
control, falls back to the full suite, hits the identical abort, and reports
SURVIVED-UNDECLARED — a false gap. Neither state is in D3's five-outcome enum.

Measured: a one-token mutant (`ALLOWED_TIERS='opus haiku'`) with `--only 9`
printed the baseline FATAL, ran no case, and emitted no `-- N/M controls passed --`
trailer.

**Fix:**
Add a sixth outcome `BASELINE-DIRTY` (FAIL in both modes; never falls back,
since the full run aborts identically), and specify that the driver classifies by
parsing per-case `PASS`/`FAIL <id>` lines and the `-- N/M controls passed --`
trailer — never by exit status, since baseline-abort, no-controls-ran and a
genuine kill all exit 1. A missing trailer is `BASELINE-DIRTY`.

**Problem:**

**Fix:**
Human decision. Trade-off: the worktree route touches no existing guard but
duplicates the fixture the harness already materializes and costs a full tree

weakens a deliberate control whose stated purpose ("the suite would validate a
checker nobody reviewed") the sweep genuinely does violate.

### 3
- status: applied
- severity: P1
- agent: feasibility
- category: Feasibility
- confidence: 100
- action_class: corroborated
- file: docs/plans/2026-07-31-mutation-sweep-harness.md
- lines: 88-96
- title: --only parses commas; expect is declared space-separated

**Problem:**
Found by coherence, feasibility and security-lens. U1 declares `expect` as "a
space-separated control-id list"; `selected()` matches on
`case ",$ONLY," in *",$1,"*` (`:744`), so a space-separated value selects nothing.
The harness then prints `FATAL: no controls ran (--only matched nothing?)` and
exits 1 — the same exit code a genuine kill produces. Every multi-control mutant
would report CAUGHT while asserting nothing: the fast path uniformly and silently
green. Measured: `--only "9 7"` → FATAL, exit 1.

security-lens adds the composition half: an `expect` beginning with `-` is parsed
as an option, the option-injection shape this repo has been bitten by three times.

**Fix:**
Store `expect` space-separated, validate each id against `^[A-Za-z0-9][A-Za-z0-9_.-]*$`
(anchor bans a leading dash and embedded spaces), and have the driver comma-join
the validated ids into a single `--only <joined>` argument. An id failing the
anchor is a build-time registry error, counted alongside ANCHOR-MISSING.

- title: Mutation confinement to the throwaway copy is unstated

**Problem:**
U2 says both "copy tree to a throwaway dir" and "restore", leaving which tree gets
written ambiguous. If an interrupted run (Ctrl-C, the CI job timeout, an early
driver exit) leaves a weakened `check-model-pins.sh` in the working tree, the next
commit ships a disabled security gate whose diff looks like a one-line edit. If the
copy is placed inside the repo instead, D5's `git status --porcelain` gate

mutated checker. Nothing constrains a mutant's `target` to resolve inside the copy
either, so a `..` component or absolute path writes wherever it points.

**Fix:**
State that the copy is created with `mktemp -d` under `${TMPDIR:-/tmp}` (never
inside the repo) and removed by a `trap ... EXIT INT TERM`; mutations apply only
inside the copy and the working tree is never written; each `target` must be a
repo-relative path resolving inside the copy after `readlink -f` (reject absolute
paths, `..` components, symlinks) or the mutant is an authoring error. Judgment
because it interacts with finding 2's undecided copy mechanism.
