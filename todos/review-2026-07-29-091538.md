**Subject:** PR #25 — `fix: pin every remaining subagent dispatch + structural enforcement (1.14.0)`

**Through-line:** the PR's pins are correct and its sweep genuinely closed
the construct — but the *enforcement mechanism written to prove it*
reproduced, inside itself, the exact defect class it exists to catch. The
checker reported `0 MISS, 0 WARN` while: an empty or moved agent tree
passed clean, `model: fable` and `model: Inherit` passed as sanctioned
pins, and leg 2's fixed-line window let a pin-shaped string in unrelated
neighbouring prose suppress a genuinely unpinned dispatch. Widening leg 2's
trigger set then found four more live dispatch sites in `review.md` that
neither the compound sweep nor the first checker saw. Nine findings applied
in-branch. The deferred tail is one operator decision (the `opus` persona
pin is a floor as well as a ceiling — on a sonnet sweep it raises cost) and
three placement/coverage judgments.

### 3
- status: applied
- severity: P1

- title: Leg 2 tested for the string `model:` in a ±12-line window, so the files densest with pin documentation were where an unpinned dispatch hid best — and its trigger regex missed four live dispatch sites

**Problem:** Two independent false-negative generators, both reproduced.
(a) The window check was `grep -q 'model:'`, which any prose *about* pins
satisfies. Traced concretely: a new fan-out added just after `review.md`'s
companion-dispatch rule (a 14-line block containing `model:` four times)
produced `0 MISS, 0 WARN` despite being a textbook unpinned generic-subagent
dispatch. (b) `DISPATCH_RE` was a five-phrase allowlist that did not match
this repo's own live dispatch wording — `review.md:341` "dispatch a Task
with", `review.md:506` "Launch ALL active agents in parallel",
`compound-refresh.md:149` "use read-only investigation subagents". Those
lines were never even candidates. Both produce the *never-appears* failure,
not the *vanishes* one, so no reviewer sees a warning go missing. A third,
smaller instance: `total=$(wc -l < "$f")` undercounts a file with no
trailing newline, clamping the window short of the match's own line.

**Fix (applied):** The pin test now requires a pin *shape*
(`model:` followed by a sanctioned tier), not the bare string. The fixed
window is replaced by markdown-block scoping — a dispatch is checked
against its own blank-line-delimited block plus the one immediately
following, which is where an author actually writes the pin; a pin in a
*preceding* block no longer counts. `DISPATCH_RE` is widened to the
uncovered phrasings and to `subagent_type`. The `wc -l` dependency is gone
with the window. Widening immediately surfaced four real sites in
`review.md`, all now resolved (three by stating the roster's
frontmatter-pin rule explicitly, one by a prose-suppression marker).
Verified in all four directions: preceding-block pin → WARN;
following-block pin → pass; suppression marker → pass; unreadable → MISS.

**Problem:** The frontmatter parser compared the first line literally

misdescribes the failure, and would land on whichever contributor's editor
introduces either.

and the first-line test is now a regex matching the closing-marker test.
