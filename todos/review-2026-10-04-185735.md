title: A failing scan pipeline drops a file's citations with no MISS

**Problem:** Every stage of the per-file `sed | sed -z | grep` carried `2>/dev/null` and was read through a process substitution, so its exit status was discarded. A fake `sed` failing on one file dropped leg 5 from 9 to 8 citations with no leg-5 MISS; the global `checked == 0` guard cannot see one lost file. A broken near-miss regex (grep exit 2) would have been just as silent.

**Fix:** Capture each stage's status via `PIPESTATUS` inside the substitution; grep 1 is normal, anything else is a MISS naming the file. Reproduced fixed with the same PATH stub.
