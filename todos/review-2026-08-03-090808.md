# Plan review — hang-path executable guard

Five personas on a 210-line plan. Strong convergence: the `capture_controls`
signature defect was found independently by all five, and the vacuous-transcript
defect by two. Both are the plan's own documented hazard classes turned back on
it — the panel earned its keep here rather than confirming a design.

Nineteen findings applied to the plan in this pass. One deferred: the P3
ride-along is an operator call the brief requires be **asked**, and this session
exposes no blocking-question tool, so it is left open and untouched.

### 1
status: applied
severity: P1
agent: coherence, feasibility, adversarial, security-lens, scope-guardian
category: correctness
confidence: 100
action_class: corroborated
file: docs/plans/2026-08-03-hang-path-executable-guard.md
lines: 115-118
title: capture_controls closes over $WORK/$COPY, which are unset during --selftest

**Problem:** The `--selftest` block runs at `scripts/run-mutation-sweep.sh:315-434`
and exits at `:433`. `WORK` is created at `:489`, `COPY` at `:513` — both after.
With `set -uo pipefail` at `:50`, an unset expansion is **fatal**, so U3's first
call aborts the whole selftest with `WORK: unbound variable` before any
assertion runs. Feasibility reproduced it in a scratch script. All five personas
found this independently.

**Fix:** parameterize fully, closing over no globals:
`capture_controls <run_dir> <suite_path> <out_file> <kill_grace> <bound>`.
Production becomes `capture_controls "$COPY" "$CONTROLS_REL" "$WORK/controls.out" 30 900`;
the selftest passes its own `mktemp -d`. Explicitly reject relocating the
`WORK`/`COPY` setup above the selftest gate — that changes startup for every
sweep run, a far larger blast radius than the extraction itself.

file: docs/plans/2026-08-03-hang-path-executable-guard.md

title: Four of U3's five assertions pass on an empty transcript

**Problem:** The repo's own selftest already asserts that an empty transcript
classifies as HARNESS-ERROR (`scripts/run-mutation-sweep.sh:401`). So a fixture
that plants the orphan but writes **nothing** still satisfies the elapsed
assertion, the CLASS assertion, and the OUTCOME assertion. The case built to
prove *truncation* → HARNESS-ERROR is satisfied by a file that was never
written. This is the plan's own "vacuous plant" hazard, mitigated for the orphan
and missed for the transcript.

**Fix:** insert a positive transcript assertion before the CLASS assertion — the
captured file must contain the fixture's baseline line AND a `^PASS  ` line
(proving the fixture wrote through the inherited fd), AND must NOT contain a
`^-- [0-9]+/[0-9]+ controls passed --$` trailer (proving the kill truncated it).
Only then is HARNESS-ERROR evidence of truncation.

### 3
status: applied
severity: P1
agent: security-lens
category: correctness
confidence: 100
action_class: mechanical
file: docs/plans/2026-08-03-hang-path-executable-guard.md
lines: 128-137
title: pgrep -f marker also matches the timeout wrapper, so the escape assertion cannot discriminate

**Problem:** `pgrep -f <marker>` matches the wrapper `timeout` process too — the
marker sits in that wrapper's own argv — so the "positive escape assertion"
passes even when the `exec -a` sleeper never started. Measured: the match
returned `timeout -k 1 6 bash -c exec -a <marker> sleep 6`. It also cannot tell
U3's orphan from U4's, since the marker is per-run rather than per-case.
Secondary: on a box without procps, `pgrep` failing reads as "plant no-oped",
inverting an environment failure into a finding — the exact inversion
`read_file` was already fixed for.

**Fix:** drop pattern matching entirely. The fixture records the sleeper's own
PID and PGID before it execs; assert escape as `kill -0 <pid>` succeeding AND
the recorded PGID differing from the driver's. Proves liveness and escape, is
immune to wrapper matches and cross-case collisions, and needs no procps —
removing `pgrep`/`pkill` as new dependencies.

### 4
status: applied
severity: P1
agent: security-lens, adversarial, feasibility
category: reliability
confidence: 100
action_class: corroborated
file: docs/plans/2026-08-03-hang-path-executable-guard.md
lines: 128-137
title: Interrupted selftest strands the escaped process — no trap exists on that path

**Problem:** `trap cleanup EXIT INT TERM` is installed at
`scripts/run-mutation-sweep.sh:495`, sixty lines **after** the selftest's
`exit 0` at `:433`. The selftest path has no cleanup trap at all. Ctrl-C, a
failed assertion, a `set -u` abort or a CI cancel between plant and reap strands
a TERM-ignoring sleeper plus a fixture tree — and SIGINT goes to the foreground
process group, which the fixture deliberately escapes. U4's ~20s window is
exactly when a developer is most likely to interrupt an apparently hung
selftest.

**Fix:** the fixture builder installs
`trap '<kill recorded pid>; rm -rf "$fixdir"' EXIT INT TERM` immediately after
creating the fixture dir, and clears it once the case's own reap is confirmed.
Stated in U2 as part of the builder's contract, not left to U3.

title: U4's negative control can block instead of failing, costing the whole weekly sweep

**Problem:** U4 waits for the hang to end, and the only thing ending it is the
fixture's own nested `timeout` — the same mechanism the case exercises. If that
misbehaves (busybox `timeout` that does not setpgid, a raised sleeper bound, a
lost kill), U4 does not fail; it **blocks**. The selftest step at
`.github/workflows/mutation-sweep.yml:84-85` carries no `timeout-minutes`, so the
block consumes the job's cap and the weekly sweep ends CANCELLED with zero
mutants — reached through a case added to make the harness safer.

**Fix:** run U4's pipe arm under its own outer `timeout`, and treat exit 124 as
an explicit FAIL naming "the pipe arm never returned; the fixture's own bound
failed". The case must be unable to outlive its own assertion.

**Problem:** the two thresholds are independent magic numbers whose *relation*

title: Section 3 states process-group separation as sufficient; it is not

**Problem:** §3 credits the escape to `run_checker`'s inner `timeout` creating a
new process group. An implementer building from §3 alone reproduces
`run_checker`'s shape — nested `timeout` whose output is captured by an inner
`$( )` — and gets **zero discrimination**, because that descendant provably
cannot hold the outer reader. Contradicted by the plan's own U2 and by
`scripts/run-mutation-sweep.sh:642-644`.

**Fix:** the escape requires **two** properties together — a descendant in its
own process group AND inheritance of the suite's plain stdout. `run_checker`'s
descendants have the first but not the second, which is precisely why the
2026-08-02 measurement saw the pipe return at the bound.

departure from case 32's "needs no cleanup, cannot leave a blocked writer"
