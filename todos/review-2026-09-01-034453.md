### 1

- file: scripts/check-residual-integrity.sh

- title: An unparseable findings file is dropped whenever a sibling parses cleanly
- resolved: 2026-09-01 — feat/check-residual-integrity, commit 018f744

**Problem:** Two bare `continue` statements (no `summary:` block; `summary:`
with no `total:`) skipped a file without incrementing any counter or emitting
any finding. Their only backstop fired at `leg1_files -eq 0` — so the moment
any other file in the tree parsed cleanly, which every real run has, the guard
was permanently disarmed. Measured: a two-file fixture, one clean file plus one
whose `total:` was typo'd to `grand_total:` and declaring `p1: 5, completed: 5`
over a body of one applied P1, reported `0 MISS, 0 WARN`, exit 0. An ordinary
typo reaches this, not an adversarial input. Additionally `grep`'s exit 2 (file
deleted or made unreadable between the walk and the read — a concurrent
`/cepa:triage`, a branch switch) was folded into exit 1 by `||`, so a
vanished file was reported as one merely lacking a summary.

**Fix:** Each path emits its own MISS; grep's exit 2 is distinguished from
exit 1 with its own message; and a walked-vs-accounted reconciliation fails
when any future `continue` is added without one. Controls `nosum`, `nototal`.
