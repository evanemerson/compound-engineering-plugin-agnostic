# Review Findings — 2026-07-29 08:09

**Subject:** PR #24 — `fix: close model-inherit leaks in dispatch paths (1.13.1)`

**Through-line:** the PR's mechanism (pin or override every dispatch) is
sound, but its blanket phrasing shipped two false factual premises about
frontmatter it didn't read (`code-simplifier` pins `opus`; one cepa agent
now pins `opus`, not `sonnet`) and one instruction stated at the wrong
layer (upstream of the delegated skill's actual Task calls, covering one
of three dispatch roles). All three applied in-branch. The deferred tail
is the observability/enforcement layer: nothing yet records which model a
dispatch actually used, the policy is restated in four places instead of
cited from one, and two dispatch sites (compound's 5-agent fan-out,
plan-review personas) remain uncovered without a documented exclusion.

### 1
- status: applied
- severity: P1
- agent: security-sentinel + silent-failure-hunter
- category: logic
- confidence: 90
- action_class: corroborated
- file: plugins/cepa/commands/review.md
- lines: 462-467
- title: Blanket sonnet override rested on a false premise and silently downgraded code-simplifier's upstream opus pin

**Problem:** The new rule claimed "the companions ship `model: inherit`
upstream" and mandated `model: sonnet` on every companion Task call.
Verified upstream frontmatter: 4 of 5 companions ship `inherit`, but
`code-simplifier` ships `model: opus` — a deliberate upstream pin. The
blanket override would silently downgrade it every run (Task-call model
takes precedence over frontmatter), the exact "normalization" this same
PR's adversarial-reviewer note forbids, with no observable trace.

**Fix (applied):** Rule rewritten to check-then-override: absent/`inherit`
frontmatter → pass `model: sonnet`; a specific pin → NO override (named
`code-simplifier`/`opus` as the current instance); missing `model:` field
entirely → file as a finding, never silently inherit; re-verify upstream
facts on every pr-review-toolkit update.

### 3
- status: applied
- severity: P2
- agent: architecture-reviewer + silent-failure-hunter
- category: contract
- confidence: 80
- action_class: corroborated
- file: plugins/cepa/commands/task.md
- lines: 350-362
- title: Override covered one of three subagent roles, was stated upstream of the actual dispatch site, and was vacuous for executing-plans

**Problem:** `subagent-driven-development` dispatches THREE generic
subagent roles per task (implementer, spec-reviewer, code-quality-reviewer)
— all plain prompt templates with no frontmatter. "(Review/verification
subagents keep their own frontmatter pins)" was false; two of three roles
would still inherit the session model, reproducing the leak one line from
its fix. The instruction also sat once in a preamble while the skill's own
repeated concrete steps (which never mention a model) drive each dispatch —
a strong drop candidate across an N-task loop. And `executing-plans` never
issues Task calls at all (separate session), so the override was vacuous
there.

**Fix (applied):** Rewritten to bind at the point of action: EVERY Task
call the skill's process issues — all three roles, every iteration —
carries `model: sonnet`; explicit warning not to rely on the skill's
templates to carry it; `executing-plans` documented as out of reach (model
chosen at session launch).
