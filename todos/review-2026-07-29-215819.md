### 12
- status: applied
- severity: P3
- agent: adversarial-reviewer
- category: logic
- confidence: 95
- action_class: mechanical
- file: plugins/cepa/scripts/check-model-pins.sh
- lines: 144-151
- title: A single NUL byte in any scanned .md made both prose legs report a clean pass

**Problem:** GNU grep treats a file containing NUL as binary: the notice goes
to **stderr** (discarded by `2>/dev/null`), stdout is empty, exit is 0. The
leg-2 readability probe `grep -c ''` succeeds, so both `scan_body` and
`scan_conditional` hit `[ -n "$hits" ] || return 0` and return silently.
Verified: a file carrying an unpinned dispatch, a one-branch marker, and one
NUL byte yielded `0 MISS, 0 WARN`, exit 0, with no line naming the file at
all; removing the NUL yielded 1 MISS. Breaks the script's own stated
principle, "a file that cannot be checked is not a pass." The reachable
cousin — invalid UTF-8 / cp1252 bytes — was tried and held; only NUL triggers
binary mode, which narrows it to P3.

**Fix (applied):** both scanning greps take `-a`, and the probe detects NUL by
byte count (`tr -d '\000' | wc -c` vs `wc -c`) and emits `UNREADABLE`. Note
the first attempt used `grep -qU $'\0'`, which is the **empty** pattern — a
bash string cannot hold NUL — and reported the entire tree unreadable; caught
by running it, and recorded here because it is an easy trap to repeat.
