# Review — PR #64 (docs/readme-restructure)

Docs and manifest PR: README restructure (593 → 488 lines), new `LOOP.md`,
manifest author identity fix, version 1.26.0 → 1.26.1.

All three findings come from `silent-failure-hunter` and share one root cause:
the new `## Verification` section described what the checker scripts *do*
without describing *how they run*. Every claim about the scripts' behavior was
accurate; the execution model was not stated, which in this repo's terms is a
promise-vs-mechanism gap.

`security-sentinel`, `architecture-reviewer`, and `previous-comments-reviewer`
returned no findings. The continuity agent verified 45 prior findings files and
confirmed the count-drift fixes from PRs #6/#7/#8 are all still intact after the
restructure.

### 1

status: applied
severity: P2
agent: silent-failure-hunter
category: documentation-accuracy
confidence: 95
action_class: corroborated
file: README.md
lines: 19-23
title: Intro claimed a script "fails the build" without disclosing that main is unprotected

**Problem:** The intro said "a script fails the build if one doesn't [declare a
model tier]." Verified live: `gh api .../branches/main/protection` returns 404
and `.../rulesets` returns 0. A red check reports loudly but physically blocks
nothing. CLAUDE.md:84-85 already documents this ("`main` is not branch-protected
today, so a red check does not physically block a merge"), and commit `caaef86`
settled it as deliberate rather than deferred. The README implied a merge gate
that does not exist.

**Fix:** Reworded to "a script in CI flags any that doesn't." The full caveat is
stated in the Verification section rather than the intro, so the summary stays
short without overstating the guarantee.

### 2

status: applied
severity: P2
agent: silent-failure-hunter
category: documentation-accuracy
confidence: 95
action_class: corroborated
file: README.md
lines: 176-199
title: Verification section described three different execution models as one manual step

**Problem:** The section said "Run it before you merge" for
`check-model-pins.sh` and said nothing about how the other checkers run. Three
distinct models were flattened into one wrong description:

- `check-model-pins.sh` — CI on `pull_request` and `push: main`
  (`model-pins.yml`)
- `check-residual-integrity.sh` — CI on `pull_request` and `push: main`
  (`residual-integrity.yml`)
- `run-mutation-sweep.sh` — weekly cron `17 6 * * 1` plus `workflow_dispatch`
  (`mutation-sweep.yml`), too slow for per-PR

A reader would either run redundantly by hand or assume the mutation sweep gates
their PR. Both halves of the real picture were absent: that CI runs these
automatically, and that CI's verdict does not block merge.

**Fix:** Each script now states how it runs, with a link to its workflow file.
The branch-protection caveat is stated plainly under `check-model-pins.sh`
("reports loudly but does not physically block a merge. Treat it as blocking
anyway"), matching CLAUDE.md's own wording.

**Problem:** `[the full table](#commands-11)` pointed at the `## Commands (11)`
heading. GitHub auto-slugifies headings, so the count was load-bearing in the
anchor: change the command count and the link 404s inside the page with no error

rather than a hypothetical.

**Fix:** Dropped the counts from the `## Commands`, `## Agents`, and `## Skills`
headings and pointed the link at `#commands`. This removes three future drift
sites, not just the one that was linked. The counts still appear where they
carry information — the `/cepa:review` row's "8 roster + 3 conditional + 5
pr-review-toolkit" and the "up to 16" figure — both verified accurate. Same
prevention pattern as commit `93af74a` earlier on this branch, which dropped
"Four scripts" rather than correcting it to six.
