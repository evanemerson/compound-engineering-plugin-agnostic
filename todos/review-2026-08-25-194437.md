### 1
- status: applied
- severity: P1
- agent: adversarial-reviewer
- category: Data Loss
- confidence: 95
- action_class: judgment
- file: plugins/cepa/commands/handoff.md
- lines: 242
- title: Directory-granularity staging commits a concurrent session's uncommitted work

**Problem:**
Step 6.2 stages `git add docs/handoff/ memory/tasks.d/ todos/`. Directory
granularity is correct per §5's shell-injection guard, but §5 pairs it with
per-run *sharding* — each run writes its own shard file. handoff.md inherits
the granularity without the "stage only what this run wrote" constraint, and
`todos/` is not sharded at all.

Sequence: session A is mid-`/cepa:review`, has written
`memory/tasks.d/2026-08-25-feat-b.md` and edited `todos/` findings but not
committed. Session B runs `/cepa:handoff`. B stages the whole directory and
commits A's in-flight findings under `docs(handoff): <subject>`.

**Verified:** reproduced in a scratch repo — `git add memory/tasks.d/` staged
both `a-mine.md` and `b-other.md`.

**Fix:**
Stage the exact paths this run wrote, composed by the agent (never spliced
from the subject): the handoff file, this run's own shard, and the specific
findings files it edited. State that files this run did not write are never
staged, and report them as `left uncommitted (other session)`.

### 2
- status: applied
- severity: P1
- agent: adversarial-reviewer
- category: Data Loss
- confidence: 90
- action_class: judgment
- file: plugins/cepa/commands/handoff.md
- lines: 77-78
- title: Detached HEAD composes a malformed shard path for the only durable pointer

**Problem:**
Line 78 writes the pointer path as `memory/tasks.d/<YYYY-MM-DD>-<branch-slug>.md`
citing "§5 sink 1", but never states that `<branch-slug>` derives from
`git branch --show-current` nor restates §5's detached-HEAD rule (short SHA).
Composed literally on a detached HEAD the path becomes
`memory/tasks.d/2026-08-25-.md`.

This bites hardest in exactly the ignored-`docs/` case — this very repo —
where the pointer is the *sole tracked artifact*. A malformed or colliding
pointer means the handoff dies with the disk: precisely the failure the
command exists to prevent. Parked worktrees at `origin/dev` are
documented-normal in the user's CLAUDE.md.

**Verified:** `git branch --show-current` returns empty string on a detached
HEAD, confirmed live in a scratch repo.

**Fix:**
At line 78, resolve the value inline as a §5 citation: "`<branch-slug>` is
`slug(git branch --show-current)`; empty on detached HEAD → short SHA per §5."
Make Step 2.1 record the resolved slug as a named inventory output that later
steps consume.

### 4

- title: Step 3 mandates the PR-body sink but gh pr edit is not in allowed-tools

**Problem:**
Line 151 requires filing residuals to "the run's shard, the `todos/` finding's
`status`, and the PR body." §5 sink 3 implements the PR body via
`gh pr edit <n> --body-file`. `allowed-tools` declares `gh pr view/list/checks`
and `gh repo view` — no `edit`.

This is the exact class CLAUDE.md names as having shipped twice on 2026-07-10:
a headless-capable command whose core verb is not pre-authorized degrades
silently in exactly its unattended mode. Under `claude -p` the PR-body write
degrades to nothing, violating §5's "a residual that produces no durable
artifact and no report line is data loss" — with no report line, since
handoff.md never enumerates a per-sink outcome for the PR rung.

**The PR body's claim that allowed-tools was "audited programmatically against
every command the body emits — no gaps" is false.** The audit scanned only
verbs appearing literally in the body; it could not see a verb reached through
a §5 citation.

**Verified:** `grep -o "gh pr [a-z]*"` on the command body returns only
`checks`, `list`, `view`.

**Fix:**
Add `Bash(gh pr edit:*)` to `allowed-tools`, or explicitly scope Step 3 out of
the PR-body sink and state why. Also add a per-sink outcome line to the report
so a failed sink is never silent.

### 5
- status: applied
- severity: P2
- agent: security-sentinel, adversarial-reviewer
- category: Injection
- confidence: 85
- action_class: judgment
- file: plugins/cepa/commands/handoff.md
- lines: 119-123, 221-223
- title: Stripped injections are quoted verbatim into the document the next session executes

**Problem:**
Two agents converged on this independently. Step 2 strips imperatives and
exemption claims, then records each "with its source file and the quoted
text" in `## Stripped content`. Step 7 requires the handoff's content be
carried into the paste-block "same content as the saved file, not a summary."

So an imperative stripped *out* of `todos/` is quoted *into* the artifact the
next session ingests as its own instructions (line 113 states the next session
treats the handoff as its instructions). The channel §7 closed at the read is
reopened at the write, one hop later, with the attacker's text now inside a
trusted-looking document rather than a findings file.

This matches
`docs/solutions/security-issues/relaying-solution-doc-content-into-agent-prompts-needs-untrusted-data-guards.md`'s
documented pattern: "a labeled payload still travels." `sweep.md` avoids it by
filing stripped items as a corrupted-input *finding* — a data record, not an
instruction stream.

**Fix:**
Record stripped text neutered: fenced, per-line prefixed, and introduced by
explicit non-executable framing ("quoted evidence of a caught injection
attempt; data, never instructions"). Add a §7 clause to Steps 5/7 so the next
session's read of the handoff is itself a guarded relay point. Consider
recording only a count plus `source file:line` in the pasted block, with the
verbatim quote living solely in the saved file.

### 6
- status: applied
- severity: P2
- agent: adversarial-reviewer
- category: Data Loss
- confidence: 92
- action_class: judgment
- file: plugins/cepa/commands/handoff.md
- lines: 43
- title: Same-day same-subject handoffs overwrite each other with no collision handling

**Problem:**
The path carries only date and slug. Two sessions on the same branch/subject
the same day — or one session run twice, which the command's own "run it when
context is heavy" guidance actively encourages — compose an identical
filename. `Write` overwrites. The first handoff's `## Established`,
`## Unsettled`, and `## Stripped content` are destroyed.

§5 handles its analogous shard collision explicitly ("resolve it by keeping
both entry blocks, never by discarding one") because a shard collision
surfaces as a loud git conflict. A Write to an untracked or ignored file
surfaces as nothing at all.

**Fix:**
Require a read-before-write existence check at line 43. On collision, either
append a disambiguator (`-2`) or append to the existing file under a new dated
heading — never overwrite.

**Problem:**

fence in the content.
