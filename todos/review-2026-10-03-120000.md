### 1

category: concurrency
confidence: 100

file: plugins/cepa/commands/compound.md
lines: 259-276
title: A reused $RUN moved the collision from the payload to the pointer

**Problem:** `mktemp` made the payloads distinct, so the collision relocated to
the single shared pointer rather than disappearing. Measured: minting twice with
`RUN=A` produced two payloads and **one** pointer, which the second mint
overwrote — orphaning run 1's payload while both runs' later blocks read run 2's
path.

**Fix:** Atomic create — `( set -C; printf ... > "$PTR" )`. A `[ -e "$PTR" ]`
test-then-write is itself a TOCTOU race. Measured: 20 concurrent noclobber
writers to one path give exactly 1 winner and 19 refusals.

### 2
status: applied
severity: P1
agent: adversarial-reviewer
category: phi-egress
confidence: 95
action_class: judgment
file: plugins/cepa/commands/compound.md
lines: 290-312, 481-505
title: The pointer's contents were used as a path with no containment check

**Problem:** The pointer sits at a predictable name in a world-writable `/tmp`,
and whatever path it held became `$P` unvalidated. Measured: a pointer aimed at
a file outside the minted prefix produced
`sealed: 1 redaction markers ... in <outside-TMPDIR>/precious.json` at rc=0 —
the scrub rewrote an unrelated file in place, and a later suppression would
`rm -f` it.

The reviewer also measured the write side: a pre-squatted **symlink** at the
pointer path was followed, destroying the target.

**Fix:** Both consumer blocks now require `$P` to match
`$TMPDIR/cepa-compound-payload-$RUN-*.json` and to be a non-symlink regular
file — the discipline `brain-client.sh` already applies to `.phiseal` ("the path
is predictable"). The symlink half was closed incidentally by finding 1's
`set -C`: noclobber refuses to follow an existing symlink. Verified — victim
contents survived both ways.

### 3
status: applied
severity: P1
agent: self (follow-up measurement from the reviewer's leftover-file note)
category: credential-at-rest
confidence: 100
action_class: mechanical
file: plugins/cepa/scripts/brain-client.sh
lines: 205-218
title: _curl's RETURN-only trap left MCP_ACCESS_KEY in /tmp on every network failure

**Problem:** `trap "rm -f '$cfg'" RETURN` fires only when the function returns
normally. The script runs under `set -e`, so a nonzero `curl` kills the shell
first and the trap never runs. The config file holds
`header = "x-brain-key: <MCP_ACCESS_KEY>"` in **plaintext**. Measured with a
curl stub exiting 7: rc=7, and `grep` found the key in the leftover file. One
file per failure, accumulating, never cleaned. Mode 600 limits it to the same
user, but it is a credential on disk nobody removes.

**Fix:** `trap ... RETURN EXIT`. EXIT covers the die-under-`set -e` path; RETURN
still covers the ordinary one so a multi-call process does not accumulate
configs until it ends. Re-measured: 0 files after 1 failed call and after 3.

### 5

file: plugins/cepa/commands/compound.md
lines: 556-565
title: Nine of ten exit paths in the writeback block left temp files in /tmp

**Problem:** Enumerated: block 2 had ten `exit 1` paths and exactly **one**
removed anything. Every other failure — resolver unresolved, writeback non-2xx,
unparseable response — left `$P` (scrubbed solution-doc content) and the pointer
in `/tmp` at mode 600. The reviewer correctly noted the new cleanup comment
asserted a guarantee the block did not provide.

**Fix:** An EXIT trap replaces the per-branch list, set *after* the containment
checks so a refused pointer can never make the trap delete a file this run does
not own. A per-branch list must stay complete as branches are added; a trap is
the mechanism. Verified by exercising the writeback-FAILED branch with a curl
stub exiting 22: 0 files left.
